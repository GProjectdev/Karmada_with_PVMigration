# HybridSpotVM Integration Contract

This repository only reconstructs retained NFS PersistentVolumes for a `PVMigration`.
It does not decide when a workload is live again, resume Karmada dispatch, change
workload placement, delete Nodes, or delete `NodeProvision` objects.

`HybridSpotVM_ManagementSystem` may watch `PVMigration` history as one input to its
own policy decisions. Its Policy Manager must treat `PVMigration.status.phase=Completed`
as historical PV transfer evidence only:

- The target PV Work was applied, verified as the expected PV, and detached with
  `preserveResourcesOnDeletion=true`.
- The retained target PV remains for later binding.
- The `PVMigration` object remains as plan history and target PVC reservation.

`Completed` is not live workload readiness. It does not prove that CRIU/FluidCR
restore finished, training resumed, traffic moved, Karmada placement changed, or
ResourceBinding dispatch was released.

## Restore Evidence Gate

Policy Manager may delete an old `NodeProvision` only after it has verified restore
evidence that is bound to the current operation. The restore evidence must match:

- the current `PVMigration.metadata.uid`;
- the current `PVMigration.status.observedGeneration`;
- a non-empty `PVMigration.status.planHash`;
- every expected `status.works[]` entry with `applied=true` and `detached=true`;
- source and target cluster names;
- ResourceBinding name;
- source workload UID;
- source PVC UID/PV name metadata used by the frozen plan;
- target PVC names; and
- the restore/checkpoint operation UID generated by the higher-level policy flow.

If any UID, generation, source metadata, target mapping, or restore operation UID does
not match, Policy Manager must keep the old `NodeProvision`. Annotation-only signals
or `Completed` alone are insufficient for deletion.

## Boundary Rules

PV-Migration-System controllers must not:

- resume or unsuspend a ResourceBinding;
- update the workload PropagationPolicy to include the target cluster;
- delete source PVs, source PVCs, Nodes, or `NodeProvision` objects; or
- infer application readiness from PV availability.

HybridSpotVM should keep the target cluster out of the workload ResourceBinding
placement while PV pre-staging runs. After the external restore gate passes, the
higher-level policy flow owns placement changes, dispatch release, and any old node
cleanup.

The regression test `TestTwoVolumeCleanupNeverResumesResourceBinding` locks the local
PV controller side of this contract for multi-volume migrations: both Works must be
detached before `Completed`, and completion must leave ResourceBinding dispatch and
placement unchanged.
